# In Loupe, a model may suspect; only code measures, and only Rules decide

Loupe examines a payslip, a statement, an invoice, a bill or an identity card and says whether it was tampered with. A vision model is good at noticing ("the net pay sits lower than its row and is a flatter black") and bad at being evidence: it cannot show its work, it is confident when wrong, and its answer changes with the prompt. A bank, an insurer or a landlord acting on "the model thinks it is fake" has nothing to show the person it turned away. The usual alternative, a fixed stack of detectors, never looks at the document the way a person would and cannot follow up on what it sees.

We keep the two apart. Words are in `src/features/loupe/GLOSSARY.md`, types in `domain/contract.ts`.

- **One Examiner, no pipeline.** One agent with tools (`look`, `run_check`, `run_code`, `load_skill`, `hypothesize`, `conclude`, `review_finding`, `finish`) chooses what to do next, as Sieve's Analyst does (ADR 0021). There are no sub-agents.
- **A model never writes a Measurement.** A Measurement is a number under one of a fixed list of Metrics (`METRICS`), with a page, a box and the code run that produced it. It comes from a named Check of the Toolkit, or from Python the Examiner wrote that called `loupe.report`; the harness reads it back from the Sandbox and parses it. A figure the Examiner states in prose is nothing.
- **A Hypothesis is settled by a Measurement.** `conclude` is refused without one, and `supported` is refused unless one of the cited Measurements trips its Rule. Refuting your own Hypothesis with a number is a normal, good outcome.
- **Findings and the Verdict are pure code** (`domain/evaluate.ts`). `evaluate` turns Measurements and a Rulebook into Findings; `decide` turns Findings into Genuine, Suspicious or Tampered. The Examiner's stance on a Sweep Finding (`review_finding`) is shown to the reviewer and never read by `decide`. To review a decisive Finding the Examiner must first have measured that place itself.
- **Rules are data** (ADR 0015): one Rule per Metric (threshold, Weight, Document kinds, on or off) plus a Policy (how many supporting Findings make a Document Tampered, which producers are editing tools and which are benign scanners and print drivers, how much of a page a pixel effect may cover before it is a re-save). Versioned per Owner. A Measurement from the Examiner's own code counts as supporting at most unless the Policy says otherwise: only a named Check, which anyone can run again, is decisive alone.
- **A Sweep sets the floor.** Before any model call, code runs every Check that fits the Document in the Sandbox. A Sweep-only Examination spends nothing on a model. On a Sample, if the Sandbox is not available, the Sweep recorded when the Corpus was rendered is used and the Trail says so.
- **Re-evaluate needs no model.** Because Findings are a function of stored Measurements and the Rulebook, a finished Examination is decided again under edited Rules by running `evaluate` and `decide`. The Trail keeps both Verdicts.
- **The harness owns the gates.** Turns, looks, Checks, code runs and USD are capped per Examination (`RUN_LIMITS`), checked before every turn and tool call. `finish` is refused until every page was looked at, every counted Sweep Finding reviewed and every Hypothesis settled.
- **The Toolkit is Python in a Vercel Sandbox with no network** (ADR 0022): pillow, numpy, OpenCV, scikit-image, pikepdf, pypdf, pdfminer, pypdfium2. Its packages live in a snapshot keyed by the hash of `requirements.txt`, built on first use; the Toolkit's own source and the Document are written when an Examination's Sandbox is made. The same code records the Corpus's expected Sweeps locally, so the golden test and the live Sweep cannot drift.

## Consequences

- Every Finding can be shown: the place, the measured value against the threshold, the Evidence layer code drew, and the code. That is what a reviewer needs, and what Loupe is: evidence for a person, not a decision about one. The page says so, with the Sweep's measured false-positive and detection rates on the Corpus (`calibrate`), which the Rules tab recomputes in the browser as a Rule is edited.
- The Sweep misses what leaves no measurable trace: an in-place edit of a PDF's text that keeps every sum consistent, a careful copy-move on an identity card. The Corpus marks such Documents `hard`, the golden test asserts they are missed, and the Calibration lists them.
- The Corpus is 53 synthetic Documents. Thresholds were tuned on train and validation only; "0 false positives" is a small-sample claim and the margins on pixel Metrics are thin (fixtures/loupe/README.md). Real paperwork will produce false alarms.
- Arithmetic on an image has no text layer to read. The Examiner reads the figures with vision and recomputes them in code; a misread digit becomes a false mismatch, which is why its own code is supporting at most.
- A new kind of check is a new Metric, a Toolkit Check and a Rule together (a unit test keeps the Toolkit's list and the contract's equal); a new value is a Rule edit.
