# Name Extraction is one Analyst with tools, not a pipeline

Name Extraction (Sieve) lists every party named in a 10 to 500 page AML Document. Recall matters most: a missed name is a missed screening hit, while an extra one costs an analyst one look. A 500-page Document is about 300k tokens. That fits in a 1M window, but one model reading all of it is the setup where recall drops: models use long inputs unevenly and miss what sits in the middle ([Liu et al., Lost in the Middle](https://arxiv.org/abs/2307.03172); [Chroma, Context Rot](https://research.trychroma.com/context-rot)). The usual answer is a fixed pipeline: chunk, extract per chunk, merge, dedupe. That pipeline fails in a predictable way. Every Document gets the same steps, so a wire ledger of 4,000 SWIFT rows and a 300-page judgment are read the same way. Nothing checks what was missed, and any step can lose a name without anyone noticing.

We run **one agent, the Analyst**, with a toolkit, and a harness that decides when it may stop. Words are in `src/features/name-extraction/GLOSSARY.md`, types in `domain/contract.ts`.

- **The Document is an environment, not a prompt.** The Analyst never reads the whole Document. It sees an `outline`, `grep`s, reads a few pages, and writes JavaScript that runs over the pages on disk in a Vercel Sandbox with no network (`run_code`). This is the Recursive Language Model idea, where the model inspects and splits a long input with code and calls sub-models on the pieces ([Zhang, Kraska & Khattab, 2025](https://arxiv.org/abs/2512.24601)). It is also the "code mode" finding: intermediate data stays in the execution environment rather than passing through the model's context ([Anthropic, Code execution with MCP](https://www.anthropic.com/engineering/code-execution-with-mcp)).
- **Sub-agents are a tool.** `spawn_readers` fans cheap Readers out over overlapping page ranges, in parallel. A Reader returns Candidates with verbatim quotes and decides nothing. Only the Analyst writes to the Register (`record_names`). Multi-agent work holds up when the helpers add information and one agent does all the writing ([Cognition, Multi-Agents: What's Actually Working, 2026](https://cognition.com/blog/multi-agents-working)). Parallel writers that each decide make choices that conflict ([Cognition, Don't Build Multi-Agents, 2025](https://cognition.ai/blog/dont-build-multi-agents)). Extraction over page ranges is the breadth-first, parallel case where sub-agents pay off ([Anthropic, multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)).
- **Skills are loaded on demand.** Long-document triage, AML name patterns, alias resolution, the recall audit and sandbox coding are playbooks. Each one costs a line of context until `load_skill` pulls it in ([Anthropic, Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)).
- **A deterministic Sweep sets the recall floor.** Before any model runs, code proposes Candidates on every page: capitalised sequences, honorifics, corporate suffixes, SWIFT `50K`/`59` fields and signature blocks. It needs no model and costs almost nothing. It catches the boring names a model skims past. Models then verify and add the names that patterns cannot see.
- **The harness enforces the Done gate.** `finish` is refused until every page was covered by a Reader or `read_pages`, and every Sweep Candidate was recorded or dismissed with a reason. The Analyst chooses how to work, and the gate makes sure it cannot skip pages. This is the recall guarantee, and it lives in code, not in the prompt.
- **The Rulebook is data, versioned per Owner.** Entity types, thresholds, exclusions and plain-language instructions can be edited. Every edit writes a new version, and every Run records the version it ran under. This follows the Harness's "rules are data, checks are code" (ADR 0015): the gate, the Sweep and the score are code, and a model never decides when the Run is done.
- **The Audit trail is append-only.** Every model call (model, tokens, cost), tool call (input, output), Skill, piece of code and the Rulebook version is a `RunEvent` ordered by `seq` and never edited. An examiner can replay why a name is in the Register or why a Candidate was dismissed. This is the Harness's rule (ADR 0018), applied per Run.

We chose this over a fixed multi-agent pipeline (chunker, extractor, deduper and verifier as separate agents) for four reasons. Recall comes from the union of the Sweep, the Readers, code and the Analyst, and the gate checks it, rather than depending on every stage being right. The Analyst spends effort where the Document needs it: code for a ledger, Readers for prose, a second look at pages where the Sweep found many Candidates and the Readers few. Cost scales with what is read once by a cheap model, not with how many agents pass the text along (multi-agent systems use about 15 times the tokens of chat, per Anthropic's post). And one writer means one place where merges and dismissals happen, which is what the Audit trail records.

## Consequences

- The Analyst's context stays small, roughly 10k to 50k tokens a turn: tool outputs, Candidates and summaries, never whole pages. With caching, a strong tool-using model is affordable there. Readers carry the page text on the cheapest faithful model. Estimates: about $0.20 for 100 pages and $0.50 for 500 pages, with `openai/gpt-6.1-terra` as Analyst and `anthropic/claude-haiku-5.5` as Reader (`docs/research/name-extraction.md`).
- Reader calls stay under 100k input tokens each. Above that, Haiku 5.5's price goes up fivefold. The stable prefix (instructions, then Rulebook) comes first and the pages come last, and calls ask for `caching: 'auto'` so parallel Readers read one cached prefix.
- Run time is not fixed: the Analyst may take more or fewer turns. A turn cap and a cost cap per Run stop a runaway. The workflow's durable steps make each model call and each sandbox run resumable.
- Code the Analyst wrote runs only in a Vercel Sandbox (a managed microVM) with a deny-all network policy and nothing in it but the pages. The Harness first ran its code on the VPS behind a Runner (ADR 0017); a managed sandbox avoids putting that load on the VPS, and the Harness has since moved to Vercel Sandbox too (ADR 0022). As in ADR 0018, the `code` event is written before the command runs, and the command is refused if that write fails.
- The Sweep is tuned on the Corpus's train and validation splits only. Its precision is low by design: every false Candidate costs a dismissal with a reason, which is the price of the recall floor.
- A Run is scored on Corpus Documents with recall as the headline, plus the missed list. A change to the Sweep, a Skill or a default model is judged by recall first and cost second.
- The recorded Replays (`public/name-extraction/replays/`) are served as static files, outside the demo gate, on purpose: the data is synthetic, they cost nothing to serve, and they show the product before sign-in. They do carry training-split Answer keys and Skill excerpts from the Audit trail, so a new Replay is recorded from the train split only, and anything that must stay behind the gate never goes in one.
