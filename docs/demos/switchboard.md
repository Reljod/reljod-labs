# Switchboard (a voice agent you can interrupt): agent notes

Read this before you change `src/features/switchboard/`, `/demos/switchboard`, `/api/switchboard/*`, `fixtures/switchboard/` or `e2e/switchboard.spec.ts`. The rules for every demo are in the root `AGENTS.md`; the layers are `docs/engineering/architecture.md`.

- A live demo at `/demos/switchboard`: the phone line of the fictional Meridia Rail. Domain language: `src/features/switchboard/GLOSSARY.md`. Decisions: `docs/adr/0029-switchboard-speech-to-speech-in-the-browser-tools-through-the-server.md`, `docs/adr/0030-switchboard-rules-at-the-tool-boundary-and-a-workflow-per-call.md`.
- **Layers.** Services in `server/services/` (`calls`, `office`, `rules`, `connect`, `wrapup`; `createSwitchboardServices` in `index.ts`) hold the business rules: caps, Owner scope, state checks, the Workflow's start and wake, the text Turn's cost and spend cap, MCP tokens. Ports are `server/ports.ts`; adapters are wired once in `server/container.ts`. The database adapters are units of work under the Call's row lock: `store.ts` (reads, the Workspace, Events), `calls.ts` (a Call's writes, the tool call through the pure Back office), `rules.ts`, `wrapup-store.ts`. They keep their own pool (`db.ts`, `timestamptz` as `Date`s; it reports to `DB_STATS`).
- **REST** (all on `switchboardApi` in `server/api.ts`: same-origin writes, the gate and the Owner, the visitor, the services, and the Owner's Workspace made on first use): `GET /state` (the page's first view), `GET|POST /calls`, `GET /calls/[id]?after=`, `POST /calls/[id]/tools|events|turns|end|callback`, `PUT /rules/[id]`, `POST /rules/[id]/restore`, `POST /records/reset`, `POST /tokens` (an MCP token), `GET /trail?before=`. No server actions. `/mcp` keeps its own bearer check (`connect.authenticate`) and calls the same services. Browser code reaches them only through `components/api.ts`.
- The voice Line is a realtime Session the browser holds with AI Gateway (`components/voice-session.ts`), opened with a one-minute secret from `server/session.ts`. The text Line's Agent (`server/line.ts`) answers a Turn at a time. Both, and the MCP server, reach the Back office only through the Calls service's `tool`. A new capability is a tool in `domain/tools.ts` with a handler in `domain/backoffice.ts`; it then exists on all three.
- Only `runBackOfficeTool` (pure, `domain/backoffice.ts`) refuses a tool call. A new Rule needs a definition in `domain/rules.ts`, a check there, and a test that it can refuse. Never enforce a Rule in the instructions alone.
- A voice Call's transcript, latencies and usage are reported by the browser (`reportedEventSchema`); treat them as the Owner's own account. Nothing but the tool call writes a Record.
- Caps are `LIMITS` in `domain/limits.ts`, taken in the services before the paid step (`server/caps.ts`). The hourly Call and Turn caps are the shared `pgRateLimiter`. A voice Call is not: `takeVoiceCall` takes the visitor's hourly Call cap and the per-Owner and global daily voice caps together, under advisory locks in one order, before the client secret is minted; the shared limiter has no per-Owner scope. The secret pins only the model; the browser sends the instructions and tools, so a voice Session's length and setup are bounded by those caps and the provider, not by the server (ADR 0029). Keep an AI Gateway budget on the Switchboard key.
- Resetting the Back office never destroys Records: they move to `switchboard.records_archive` and the purge cron removes them after 30 days.
- Each Call has one Workflow (`server/call-workflow.ts`): the server-side cut-off, the Wrap-up, the Callback sleep. Its steps (`server/call-steps.ts`) are replay keys: keep their names and file; each body is one call to the Wrap-up service.
- **Stubbing.** An e2e request without `x-e2e-live: 1` gets the stubbed container: the canned Agent of `domain/stub.ts` on the text Line (a Call it starts records `STUB_MODEL`, whose Wrap-up is written by code), a canned note writer and Sandbox, and a Session grant that opens nothing. The Back office, its Rules, the caps, the database and the Workflow stay real. An MCP token minted by the stubbed services carries `stub`, so an outside client on it keeps the canned Agent.
- Env: optional `SWITCHBOARD_AI_GATEWAY_API_KEY` (falls back to `DOCUMENT_COMPLIANCE_AI_GATEWAY_API_KEY`), `DATABASE_URL`; shares `RATE_LIMIT_SALT` (it signs the MCP tokens) and `E2E_BYPASS_TOKEN`. Data lives in the `switchboard` schema (`supabase/migrations/20261119150000_switchboard.sql`, plus `20261127140000_soft_deletes_and_caps.sql` for the voice caps and the Records archive; added with `git add -f`), reached directly; only `switchboard.workspaces` is in `access.owned_tables`. The Sandbox authenticates like Sieve's.
- Sample callers: lines in `domain/samples.ts`, clips in `public/switchboard/samples/` (README in `fixtures/switchboard/`).
- `e2e/switchboard.spec.ts` is skipped unless `E2E_SWITCHBOARD=1`, and runs stubbed. `E2E_SWITCHBOARD_LIVE=1` adds three real runs (they send `x-e2e-live: 1`: a typed Call, and two Sample callers' audio into a real Session: turn-taking and a Barge-in). Run it only when asked.
- Tests: `server/services/services.test.ts` (fake ports: caps before what they pay for, a Call never without its Workflow, Owner scope, Rule edits, MCP tokens, the Wrap-up never paying twice), `domain/backoffice.test.ts` (every Rule can refuse), `domain/scorecard.test.ts`, `domain/rules.test.ts`, `domain/limits.test.ts`, `domain/models.test.ts` (cost), `domain/hearing.test.ts`, `server/sandbox.test.ts` (no network), `components/voice-session.test.ts` (Barge-in).
