# Switchboard (a voice agent you can interrupt): agent notes

Read this before you change `src/features/switchboard/`, `/demos/switchboard`, `/api/switchboard/*`, `fixtures/switchboard/` or `e2e/switchboard.spec.ts`. The rules for every demo are in the root `AGENTS.md`.

- A live demo at `/demos/switchboard`: the phone line of the fictional Meridia Rail. Domain language: `src/features/switchboard/GLOSSARY.md`. Decisions: `docs/adr/0029-switchboard-speech-to-speech-in-the-browser-tools-through-the-server.md`, `docs/adr/0030-switchboard-rules-at-the-tool-boundary-and-a-workflow-per-call.md`.
- The voice Line is a realtime Session the browser holds with AI Gateway (`components/voice-session.ts`), opened with a one-minute secret from `server/session.ts`. The text Line (`server/line.ts`) is the same Agent a Turn at a time. Both, and the MCP server (`/api/switchboard/mcp`), reach the Back office only through `callTool` in `server/calls.ts`. A new capability is a tool in `domain/tools.ts` with a handler in `domain/backoffice.ts`; it then exists on all three.
- Only `runBackOfficeTool` (pure, `domain/backoffice.ts`) refuses a tool call. A new Rule needs a definition in `domain/rules.ts`, a check there, and a test that it can refuse. Never enforce a Rule in the instructions alone.
- A voice Call's transcript, latencies and usage are reported by the browser (`reportedEventSchema`); treat them as the Owner's own account. Nothing but `callTool` writes a Record.
- Caps are `LIMITS` in `domain/limits.ts`, taken in `takeRate` (`server/rate.ts`) in Postgres under advisory locks. A voice Call takes the visitor's hourly Call cap and the per-Owner and global daily voice caps together, in `startCall`, before the client secret is minted. The secret pins only the model; the browser sends the instructions and tools, so a voice Session's length and setup are bounded by those caps and the provider, not by the server (ADR 0029). Keep an AI Gateway budget on the Switchboard key.
- Resetting the Back office never destroys Records: they move to `switchboard.records_archive` and the purge cron removes them after 30 days.
- Each Call has one Workflow (`server/call-workflow.ts`): the server-side cut-off, the Wrap-up, the Callback sleep. In-call writes are POST routes (`domain/api.ts` says why); other writes are server actions.
- Env: optional `SWITCHBOARD_AI_GATEWAY_API_KEY` (falls back to `DOCUMENT_COMPLIANCE_AI_GATEWAY_API_KEY`), optional `SWITCHBOARD_DATABASE_URL` (falls back to `CLIENT_MANAGER_DATABASE_URL`); shares `RATE_LIMIT_SALT` (it signs the MCP tokens) and `E2E_BYPASS_TOKEN`. Data lives in the `switchboard` schema (`supabase/migrations/20261119150000_switchboard.sql`, plus `20261127140000_soft_deletes_and_caps.sql` for the voice caps and the Records archive; added with `git add -f`), reached directly; only `switchboard.workspaces` is in `access.owned_tables`. The Sandbox authenticates like Sieve's.
- Sample callers: lines in `domain/samples.ts`, clips in `public/switchboard/samples/` (README in `fixtures/switchboard/`).
- `e2e/switchboard.spec.ts` is skipped unless `E2E_SWITCHBOARD=1`; the Agent's Turns are stubbed (`x-switchboard-stub` with the e2e token). `E2E_SWITCHBOARD_LIVE=1` adds three real runs (a typed Call, and two Sample callers' audio into a real Session: turn-taking and a Barge-in). Run it only when asked.
