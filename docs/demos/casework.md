# Casework (the Specialist desk): agent notes

Read this before you change `src/features/casework/`, `/demos/casework`, `/api/casework/*` or `fixtures/casework/`. The rules for every demo are in the root `AGENTS.md`.

- A live demo at `/demos/casework`. Domain language: `src/features/casework/GLOSSARY.md`. Decision: `docs/adr/0007-jobs-as-mcp-tools-on-durable-workflows.md`.
- The desk's chat calls its own MCP server with a session token (`sessionToken` in `server/session.ts`, minted per message in `server/chat.ts`): a signed `{ sessionId, owner, exp }` that lives an hour (`SESSION_TOKEN_SECONDS`). The server refuses it once expired, and every tool checks the Desk still belongs to the token's Owner (`sessionOf` in `server/mcp.ts`); only the outside client's desk (`CASEWORK_MCP_TOKEN`) has no Owner.
- Jobs and Pipelines live in `src/features/casework/domain/jobs.ts` and `pipelines.ts`; each becomes an MCP tool on `/api/casework/mcp` automatically. Rules are pure functions in `domain/rules/`; only Sort, Read, Adjudicate and Decide call a model.
- Fixtures: `fixtures/casework/` (README there). Labels follow `domain/document-kinds.ts`; `golden.test.ts` scores the rules against them per train/validation/test split. Tune rules on train and validation only.
- Env: `DATABASE_URL` (the Supabase transaction pooler, port 6543; the `casework` schema is reached directly with postgres.js, `server/db.ts`), `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` (Storage only); optional `CASEWORK_AI_GATEWAY_API_KEY` (falls back to `DOCUMENT_COMPLIANCE_AI_GATEWAY_API_KEY`), optional `CASEWORK_MCP_TOKEN` for outside MCP clients, optional `CASEWORK_OCR=0`; shares `RATE_LIMIT_SALT` and `E2E_BYPASS_TOKEN`. Data lives in the `casework` schema, reached directly (not through the Data API), and the private `casework` bucket (through supabase-js Storage). `pnpm seed:casework` needs the same three variables.
- Caps are `LIMITS` in `domain/limits.ts`. A chat message takes `takeChatTurn` before the model is called: the visitor's 40 an hour, the demo's daily turns, the Owner's daily spend summed over all their Desks, then the Desk's own $2, all in `casework.take_chat_turn` under one advisory lock. A new Desk resets only the Desk's cap, so its message offers a new desk only when the Owner still has room. A Run is counted and created in one step by `casework.create_run` (visitor hour, demo day, one Run per Desk, the Owner's daily spend and the Desk's cap). Spend is recorded as model calls finish, so turns or a Run already in flight can take an Owner a little past a cap: at most one turn's cost per turn in flight. Both need `supabase/migrations/20261127130000_casework_caps.sql` applied before this code is deployed.
- Uploads: the browser's type, size and pages only open a slot. `finishUpload` records what Storage holds: the real size, the type checked by its first bytes, and only the page images that were stored (`domain/uploads.ts`). A ticket expires after two hours and is good once (an upload's path is recorded once; a unique index backs it). The bucket takes only PDF, CSV, JPEG and PNG up to 10 MB (`supabase/migrations/20261127130100_casework_uploads.sql`).
- Storage: the `casework` bucket holds the seeded Cabinet under `cabinet/<scenario>/<slug>/` and Desk uploads under `uploads/<session id>/<uuid>/` (the file and its `page-N.jpg` images). Deleting a Desk (the 30-day expiry cron, or an Owner purge) cascades its rows but leaves its `uploads/<session id>/` objects in Storage.
