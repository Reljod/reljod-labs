# Floorwalk (a site walk, watched): agent notes

Read this before you change `src/features/floorwalk/`, `/demos/floorwalk`, `/api/floorwalk/*`, `fixtures/floorwalk/` or `e2e/floorwalk.spec.ts`. The rules for every demo are in the root `AGENTS.md`.

- A live demo at `/demos/floorwalk` in three places (Walk, Standard, Under the hood): the Walker (Gemini 4 Neon) watches body-camera footage of a walk through a warehouse or shop and reports what breaks the Standard, with the second and a box. Domain language: `src/features/floorwalk/GLOSSARY.md`. Decision: `docs/adr/0036-floorwalk-the-model-watches-code-decides.md`.
- The model reports; code decides. A Sighting becomes a Finding only through `checkSighting` (`domain/walk.ts`); the Score and the Fix list come from `scoreWalk`, which reads only Findings and the Standard. Rules are data in `domain/rules.ts`. A new Rule is a Rule there (and in a Sample's `planted` list if a Sample shows it); never score in the prompt.
- The Walker's output is NDJSON parsed line by line (`parseLine`) and is data: never rendered as HTML, never followed. Every sentence it reads is in `domain/brief.ts`; an Ask's question is quoted as data.
- Samples are rendered, not filmed: `fixtures/floorwalk/scene.html` builds each Site in `domain/sites.ts` in Three.js, and `pnpm render:floorwalk-samples` writes the MP4s and `domain/answer-key.generated.json` (the ground truth: when and where each planted problem and decoy is in view). After changing a Site, re-render, then re-record the real Walks the page replays (`scripts/record-floorwalk-walks.mts` against a running app; it spends about four cents a Sample) and format them with biome.
- No saved data. The only table is `floorwalk.rate_hits` (`supabase/migrations/20261121160000_floorwalk.sql`, added with `git add -f`, apply before deploying); uploads go to the private `floorwalk` bucket under `uploads/<UTC hour>/<owner>/` (`domain/uploads.ts`), are checked again (owner, type, size, length) before the call, and any hour folder older than `LIMITS.uploadHours` is swept by `sweepUploads` after the next page view, Walk, Ask or upload by anyone; there is no cron. Caps are `LIMITS` in `domain/limits.ts`, taken with `take()` in `server/rate.ts` before the model is called.
- A Sample not on disk is fetched from this deployment's own address (`sampleOrigin` in `server/footage.ts`: `VERCEL_URL` and friends), never from the request's origin; a local origin is used only in development.
- Env: optional `FLOORWALK_AI_GATEWAY_API_KEY` (falls back to `DOCUMENT_COMPLIANCE_AI_GATEWAY_API_KEY`), `FLOORWALK_MODEL` (default `google/gemini-4-neon`), `FLOORWALK_DATABASE_URL` (falls back to `CLIENT_MANAGER_DATABASE_URL`); shares `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `RATE_LIMIT_SALT` and `E2E_BYPASS_TOKEN`.
- Tests: `e2e/floorwalk.spec.ts` replays a Recording and walks a Sample with the scripted Walker (`x-floorwalk-stub` with the e2e token: no model, no database write). `E2E_FLOORWALK_LIVE=1` walks one Sample on the real model (about four cents). Run it only when asked.
