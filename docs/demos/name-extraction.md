# Sieve (Name Extraction): agent notes

Read this before you change `src/features/name-extraction/`, `/demos/name-extraction`, `/api/name-extraction/*`, `fixtures/name-extraction/`, `sandbox-quickstart/` or `e2e/name-extraction.spec.ts`. The rules for every demo are in the root `AGENTS.md`; the layers below follow `docs/engineering/architecture.md`.

- A live demo at `/demos/name-extraction`: one Analyst agent lists every party named in a 10 to 500 page AML document, recall first. Domain language: `src/features/name-extraction/GLOSSARY.md`. Decision: `docs/adr/0021-one-analyst-with-tools-not-a-pipeline.md`; research and cost model: `docs/research/name-extraction.md`.
- No fixed pipeline. The Analyst picks its tools (`domain/contract.ts` `TOOLS`): Readers (sub-agents over page ranges), Skills (`src/features/name-extraction/skills/`), `run_code` in a Vercel Sandbox with no network, and the model-free Sweep. The harness owns the Done gate and the caps (turns, Readers, USD); the model never does.

## Layers

- **Services** (`server/services/`, wired in `services/index.ts`): `runs` (list, detail, `get_run`'s report, start, stop, the Audit trail stream), `preview` (a Document's overview, its pages with marks in chunks of `LIMITS.previewPages`, a Run against the Answer key), `rulebooks` (versions, save), `uploads` (open an Upload) and `connect` (mint an Owner's MCP token), plus `firstView` for the page. Owner scoping, the caps, state rules and the trail writes are all here; none imports `next/*`. Refusals are `@/platform/errors` errors: another Owner's Run or Upload is a 404, a cap a 429, a Run whose workflow would not start a 409.
- **Ports** (`server/ports.ts`): the repositories (`repository.ts`, adapted in `adapters.ts`), the bucket, the Document loader (`document.ts`), the Workflow SDK, the token signer, the clock and the poll wait; on the workflow side the Analyst's model, the Readers and the Sandbox. The pure row shapes and `toSummary` are in `server/run-row.ts`.
- **Containers**: `server/container.ts` (`sieve(mode)`) for requests; `server/work-container.ts` (`analystWork(mode)`) for the workflow's steps, kept apart because `container.ts` starts the workflow and so imports it. Caps are `LIMITS` in `domain/limits.ts` (taken in the services for the app and the MCP server alike) and `RUN_LIMITS` in `server/toolkit/state.ts` (taken by the workflow). Sieve has no `rate_hits` table: the Run caps are counted and the row inserted under one lock in `name_extraction.create_run`, the Rulebook cap in `save_rulebook`, the Upload cap by a count in the service.
- **REST** (`server/api.ts`: `sieveApi` = `sameOrigin` → `withOwner` → `withVisitor` → `withServices(sieve)` → `caller`; paths, request schemas and answers in `domain/api.ts`, browser wrappers in `components/api.ts`):
  - `GET /api/name-extraction/runs`, `POST …/runs` (start; `{ runId }`), `GET …/runs/[runId]`, `GET …/runs/[runId]/events?after=` (NDJSON, about 280 s per connection), `POST …/runs/[runId]/stop`, `GET …/runs/[runId]/comparison`.
  - `GET …/preview/overview?corpus=|upload=|run=` and `GET …/preview/pages?…&from=&to=`: the 500-page preview asks for its 12-page chunks in parallel; each answer is `private, no-store` with an ETag (a preview before a Run follows the Owner's current Rulebook, so it is never shared-cached), and the page keeps a finished Run's chunks in memory for the visit (`components/read-cache.ts`).
  - `GET|POST /api/name-extraction/rulebooks` (a save answers with the version it wrote), `POST …/uploads` (a row and a signed Storage URL; the pages go straight to the bucket), `POST …/tokens` (an MCP bearer, shown once).
  - `/api/name-extraction/mcp` checks its own bearer (no cookies, no `withOwner`) and calls the same services. There are no server actions.
- The page (`src/app/demos/name-extraction/page.tsx`) reads its first view through `sieve(mode).firstView` behind `<Suspense>`.
- Each Analyst turn and each tool call is a Workflow step (`server/run-workflow.ts`); every step body calls `analystWork(ctx)` (`server/analyst.ts`, `createAnalystWork`). Do not rename or move the steps, the workflow or the file. Every event goes to `name_extraction.run_events`, the append-only Audit trail.

## Stubs and e2e

- A stubbed e2e request (the e2e token without `x-e2e-live: 1`) gets `sieve({ stub: true })`: the Runs it starts carry `ctx.stub`, so their steps get the scripted Analyst, the Sweep-backed Readers and no Sandbox (`server/stubs.ts`). The script spawns Readers over every page, dismisses the Sweep's leftovers and calls `finish`, which the real Done gate then lets through; nothing is billed and no cost event is written. A token the stubbed suite mints carries `stub` in its signed claims, so the MCP Runs it starts are stubbed too. The gates, the caps, the workflow, Storage and the database stay real.
- `e2e/name-extraction.spec.ts` runs a whole stubbed Run on the 10-page Corpus Document from the page, saves and restores a Rulebook, and checks that another Owner's Run is a 404 on every route. It deletes the `e2e` Owner's Runs, Rulebooks and Uploads before and after.

## Rules that stay

- Corpus: generated from seeds in `domain/corpus/` (README in `fixtures/name-extraction/`), splits train/validation/test, every split with a 500-page Document. Tune the Sweep on train and validation only. `pnpm render:name-extraction-corpus` rewrites the manifest and the sample PDFs.
- `pnpm eval:name-extraction [ids] [--split=]` runs the real Analyst against the Corpus without a server or database (`server/eval.ts` swaps the trail's sink with `setRunSink`). It spends money and starts Sandboxes: run it only when asked.
- Env: `DATABASE_URL`, `NAME_EXTRACTION_AI_GATEWAY_API_KEY`, `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` (Storage only); outside MCP clients use a per-Owner token minted under "Connect a client"; the Sandbox authenticates with OIDC (automatic on Vercel, `VERCEL_OIDC_TOKEN` from `vercel env pull` locally). Shares `RATE_LIMIT_SALT` (it signs every Sieve MCP token) and `E2E_BYPASS_TOKEN`. Data lives in the Supabase `name_extraction` schema (migrations `20261117200000_name_extraction.sql`, `20261128161000_name_extraction_rest_indexes.sql`), on the shared pool (`db()` from `src/server/postgres.ts`), and the private `name-extraction` bucket, reached through supabase-js Storage.
- `sandbox-quickstart/` is the standalone Vercel Sandbox smoke test (`pnpm exec tsx index.ts` there prints `Hello from generated code`).
