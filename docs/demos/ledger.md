# Ledger (the site's cat mascot): agent notes

Read this before you change `src/features/ledger/`, `/demos/ledger`, `/ask/*`, `/api/ledger/*` or `e2e/ledger.spec.ts`. The rules for every demo are in the root `AGENTS.md`; the layers are `docs/engineering/architecture.md`.

- A live demo at `/demos/ledger`. Ask sessions take apart the About page (`AboutSections`), not the landing page.
- Domain language: `src/features/ledger/GLOSSARY.md`. Decisions: `docs/adr/0006-llm-plans-what-browser-plans-where.md`, `docs/adr/0007-joins-are-ledgers-only-words-on-the-answer.md`.
- **Layers.** `LedgerService` (`server/service.ts`) opens Ask sessions and streams Builds: Owner scope, the cap before the planner, step validation, storage. Ports are `server/ports.ts`; `server/container.ts` wires the SQL (`repository.ts`, on the shared `db()`), the caps (`rate-limit.ts`) and the planner (`planner.ts` live, `stub-plans.ts` canned).
- **REST** (on `ledgerApi`, `server/api.ts`: same-origin writes, the gate and the Owner, the visitor, the service): `POST /api/ledger/sessions` (`{ question }` → `StartAskResult`) and `POST /api/ledger/sessions/[id]/builds` (`{ question }` → NDJSON `BuildEvent`s). Browser code reaches them only through `components/api.ts`. No server actions. `/ask/<id>` reads its session through the same service; another Owner's is a 404.
- Env: `DATABASE_URL`, `LEDGER_AI_GATEWAY_API_KEY`, optional `LEDGER_MODEL` (default `zai/glm-5.3-flash`); shares `RATE_LIMIT_SALT` and `E2E_BYPASS_TOKEN`. Data lives in the Supabase `ledger` schema, reached directly with postgres.js, not through the Data API.
- Rate limits: `LIMITS` in `src/features/ledger/domain/limits.ts` (Builds per visitor per hour, Builds site-wide per day). A Build takes a hit in `ledger.rate_hits` through `ledger.take_rate_hit` (advisory lock, count and insert in one call) while its session loads, before the planner is asked, so a dropped stream or parallel posts still count; opening a session only peeks. Over a limit, the visitor gets their own Owner's recent answer instead. It is not the shared `pgRateLimiter`: the table has no kind column and the SQL function already takes under its lock. Migration: `supabase/migrations/20261127110000_ledger_rate_hits.sql`.
- Anything on the About page Ledger may cut carries `source(sourcePath.…)`; the content tree in `src/features/ledger/domain/content-tree.ts` must name the same paths.
- **Stubbing.** `e2e/ledger.spec.ts` runs stubbed by default: an e2e request without `x-e2e-live: 1` gets the container's canned planner (the Build plans in `server/stub-plans.ts`), run through the real validation, caps, storage and stream. `x-ledger-force-limit: 1` (honoured only with the e2e token) shows the limited path without spending the cap. `E2E_LEDGER_LIVE=1 pnpm test:e2e e2e/ledger.spec.ts` sends `x-e2e-live: 1` and asks the real model; run it only when asked, like the rest of the suite.
- Tests: `server/service.test.ts` (fake ports: Owner scope, the cap before the planner, only validated steps stored), `domain/build-plan.test.ts` (invented sources and excerpts are dropped), `domain/content-tree.test.ts`, and the Postgres ones `server/rate-limit.db.test.ts` and `server/repository.db.test.ts` (skipped without `DEMO_TEST_DATABASE_URL`).
