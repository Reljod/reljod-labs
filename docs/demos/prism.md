# Prism (single-forward-pass Decision Models): agent notes

Read this before you change `src/features/prism/`, `/demos/prism`, `/api/prism/*` or `e2e/prism.spec.ts`. The rules for every demo are in the root `AGENTS.md`; the layers are in `docs/engineering/architecture.md`.

- A live demo at `/demos/prism` in four places (Prism, Tribunal, Cascade, Lab): showcases November 2026 non-generative Decision Models (`experimental_decide` via Vercel AI Gateway: `microsoft/decision-1.1`, `liquid/d1.2-ultra`, `perplexity/pplx-decider-v1.3`, `nace-ai/drex-max-finance`, `google/gemini-decision-1`, `baseten/joey-1`) returning calibrated probabilities in one forward pass with zero output tokens. Domain language: `src/features/prism/GLOSSARY.md`.
- Pure decision physics (`domain/routing.ts`): `shannonEntropy`, `compositeRisk`, `routeChute`, and `tribunalConsensus` run deterministically in code, so threshold sliders re-route Slips and Cascade bins at 60fps with zero extra model calls. The page has no first view to read: it is static until the visitor fires a Refraction.
- Layers: `server/service.ts` (`PrismService`: `refract`, `tribunal`, `cascade`) over the ports in `server/ports.ts` (`Decider`, `rate`, `now`), wired in `server/container.ts`. `server/api.ts` is the route stack (`sameOrigin`, `withOwner`, `withVisitor`, `modelUnavailable`, `withServices(prism)`).
- Endpoints, all `POST`, gated and matched in `src/proxy.ts`:
  - `/api/prism/refract`: one Refraction, JSON. A Decision Model failure (`ProviderUnavailableError`) answers 503 with its message.
  - `/api/prism/tribunal`: one call per Juror, streamed as NDJSON (`juror.result` / `juror.error`, then `tribunal.done`).
  - `/api/prism/cascade`: one call per Slip, three at a time, streamed as NDJSON (`item.decided` / `item.error`, then `cascade.done`).
- Caps live in `LIMITS` (`domain/limits.ts`) and are taken by the service with `pgRateLimiter` over `prism.rate_hits` (`units` and `owner` columns) before the first model call or stream starts, counting actual Decision Model calls: 1 for refract, the Juror count for tribunal, the Slip count for cascade. Each kind has a visitor hour and an everyone day (`refractionsPerDay`, `tribunalCallsPerDay`, `cascadeCallsPerDay`, 2,000 each: the shared limiter counts per kind, so the old 6,000 for all kinds together is split three ways). Trusted `e2e` visitors are never limited.
- Env: optional `PRISM_AI_GATEWAY_API_KEY` (falls back to `DOCUMENT_COMPLIANCE_AI_GATEWAY_API_KEY`); the shared `DATABASE_URL` pool (`db()` in `src/server/postgres.ts`), `RATE_LIMIT_SALT` and `E2E_BYPASS_TOKEN`. Migration: `supabase/migrations/20261120120000_prism.sql`; `prism.rate_hits` is registered in `access.owned_tables`. The limiter's everyone-count uses `rate_hits_kind_created_idx` (`20261128000000_rate_hits_kind_created_indexes.sql`).
- Stubbing: an e2e request (the e2e token) without `x-e2e-live: 1` gets the container's `stubDecider` (`server/decide.ts`): deterministic calibrated answers after a short per-model delay, no gateway call and no spend. Gates, caps and the database stay real.
- Tests: `server/service.test.ts` (the cap is taken with the right units and Owner before any model call; a refusal never reaches the model) and `domain/prism.test.ts` (the Gates route in code and can send a Slip somewhere other than Auto-Clear; a Tribunal can be split). `e2e/prism.spec.ts` is skipped unless `E2E_PRISM=1` and runs stubbed by default. Run it only when asked.
