# Loupe (a forensic examiner for documents): agent notes

Read this before you change `src/features/loupe/`, `/demos/loupe`, `/api/loupe/*`, `fixtures/loupe/`, `public/loupe/` or `e2e/loupe.spec.ts`. The rules for every demo are in the root `AGENTS.md`.

- A live demo at `/demos/loupe` in four tabs (Examine, Rules, Under the hood, Connect; `?tab=`, `?x=<examination id>`): one Examiner decides whether a payslip, statement, bill, invoice or identity card (PDF or image) was tampered with. Domain language: `src/features/loupe/GLOSSARY.md`. Decisions: `docs/adr/0027-loupe-findings-are-measured-by-code.md`, `docs/adr/0028-loupe-examiner-tools-are-the-mcp-server.md`.
- A model may suspect; only code measures; only Rules decide. A Measurement comes from a Toolkit Check or from the Examiner's own code calling `loupe.report`, never from model text. `domain/evaluate.ts` (`evaluate`, `decide`, `doneGate`) is pure and is the only place a Finding or a Verdict is made. Rules are data in `domain/rules.ts` (one per Metric, plus the Policy), versioned per Owner; Re-evaluate runs `evaluate` over stored Measurements with no model call.
- The Examiner reaches everything through the Loupe MCP server (`/api/loupe/mcp`, `server/mcp.ts`), in process, with a token bound to its Examination. A new capability is a new MCP tool calling a server function the app's actions also call (`server/tools.ts`, `examinations.ts`, `rulebooks.ts`, `uploads.ts`). An Examination's state is one JSON column changed only by the tools under a row lock (`mutateState`).
- The Toolkit is Python (`src/features/loupe/toolkit/loupe`, pinned `requirements.txt`) and runs in a Vercel Sandbox with no network; its packages are in a snapshot keyed by the requirements' hash (`loupe.toolkit_snapshots`, built on first use). A new Metric needs the contract (`METRICS`, `CHECKS`), the Toolkit (`contract.py`) and a Rule together. After changing the Toolkit or the Corpus run `pnpm render:loupe-corpus` (needs `uv`), which also rewrites `server/toolkit.generated.json` and `domain/corpus.generated.json`; commit them. Corpus PDFs and the Samples' `document.pdf` need `git add -f`.
- Corpus: `fixtures/loupe/` (README there; Meridia, SPECIMEN), 53 Documents in train/validation/test with a Manifest of every Tamper. `domain/golden.test.ts` scores the model-free Sweep against it. Tune thresholds on train and validation only. Samples are static files under `public/loupe/samples/`; a Sample card never says whether it was tampered with.
- Workflow: `server/workflow.ts` (`loupeExamination`) holds only pure code; every step is in `server/steps.ts`. Do not import a module that uses Node built-ins or `postgres` into `workflow.ts`, and do not rename or move the steps while an Examination runs.
- Data lives in the `loupe` schema (`supabase/migrations/20261119140000_loupe.sql`), reached directly like the Harness's, and the private `loupe` bucket (Uploads, page images, Evidence layers; served to their Owner by `GET /api/loupe/examinations/[id]/asset`). `loupe.owners` is the only table in `access.owned_tables`; everything cascades from it. The Trail (`examination_events`) and the Audit trail (`audit_events`) refuse UPDATE and DELETE.
- Env: `DATABASE_URL`, `LOUPE_AI_GATEWAY_API_KEY` (falls back to `DOCUMENT_COMPLIANCE_AI_GATEWAY_API_KEY`), `LOUPE_MODEL`; shares `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `RATE_LIMIT_SALT` (it signs every Loupe MCP token) and `E2E_BYPASS_TOKEN`. The Sandbox authenticates like Sieve's (OIDC on Vercel, `VERCEL_OIDC_TOKEN` locally); without it only Samples can be examined, from their recorded Sweep.
- Caps are `LIMITS` and `RUN_LIMITS` in `domain/limits.ts`, applied in the server functions for the app and the MCP server alike.
- `e2e/loupe.spec.ts` runs with a scripted Examiner under the e2e bypass (no model; the MCP journey runs the Sweep in a real Sandbox). `E2E_LOUPE_LIVE=1` adds one real Examination (about five cents). Run it only when asked, like the rest of the suite.
