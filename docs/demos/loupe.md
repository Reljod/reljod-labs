# Loupe (a forensic examiner for documents): agent notes

Read this before you change `src/features/loupe/`, `/demos/loupe`, `/api/loupe/*`, `fixtures/loupe/`, `public/loupe/` or `e2e/loupe.spec.ts`. The rules for every demo are in the root `AGENTS.md`; the layers below follow `docs/engineering/architecture.md`.

- A live demo at `/demos/loupe` in four tabs (Examine, Rules, Under the hood, Connect; `?tab=`, `?x=<examination id>`): one Examiner decides whether a payslip, statement, bill, invoice or identity card (PDF or image) was tampered with. Domain language: `src/features/loupe/GLOSSARY.md`. Decisions: `docs/adr/0027-loupe-findings-are-measured-by-code.md`, `docs/adr/0028-loupe-examiner-tools-are-the-mcp-server.md`.
- A model may suspect; only code measures; only Rules decide. A Measurement comes from a Toolkit Check or from the Examiner's own code calling `loupe.report`, never from model text. `domain/evaluate.ts` (`evaluate`, `decide`, `doneGate`) is pure and is the only place a Finding or a Verdict is made. Rules are data in `domain/rules.ts` (one per Metric, plus the Policy), versioned per Owner; Re-evaluate runs `evaluate` over stored Measurements with no model call.

## Layers

- **Services** (`server/services/`, wired in `services/index.ts`): `examinations` (list, detail, asset, the Trail stream, start, stop, reevaluate, Audit trail, Corpus, the page's first view), `rulebooks` (versions, save, `edit_rule`, `list_rules`, Calibration), `uploads`, `connect` (mint an Owner's MCP token), `tools` (the Examiner's eight tools, for the MCP server and "run the Check again") and `examiner` (the workflow's side: prepare, Sweep, opening, turn, tool call through MCP, end). `ending.ts` and `shared.ts` are what they share (ending and scoring an Examination, Trail writes, a Document for the Sandbox). Owner scoping, caps, state rules and Audit writes are all in the services; none imports `next/*`. Refusals are `@/platform/errors` errors; a tool's refusal the model should read is an outcome with `ok: false`.
- **Ports** (`server/ports.ts`): repositories (`repository.ts`: Examinations, Trail, Rulebooks, Uploads, Audit), Loupe's own rate limiter, Storage, a Sample's file, the Toolkit Sandbox, the Examiner's model, the workflow, the in-process MCP server, the token secret and the clock. `server/examination.ts` is the pure row, state and `standingOf`.
- **Container** (`server/container.ts`): `loupe(mode)`. Live: Vercel Sandbox (`sandbox.ts`, `live` only where it is set up) and the gateway Examiner (`examiner-model.ts`). Stubbed (an e2e request without `x-e2e-live: 1`): the scripted Examiner and the recorded Sandbox (pages, Sweep and Checks from the Sample's recording; code runs answer a canned line). Gates, caps, the database, Storage and the Workflow SDK are real in both. The stub follows an Examination: one the stubbed suite starts is marked `state.stub`, its workflow steps take the stubbed services (`examinerFor`), and its Examiner's tokens and a token the stubbed suite mints carry `stub` in their signed claims, so the MCP server answers them from the stubbed services too.
- **REST** (`server/api.ts`: `loupeApi` = `sameOrigin` → `withOwner` → `withVisitor` → `withServices(loupe)` → `who`; paths and schemas in `domain/api.ts`, browser wrappers in `components/api.ts`):
  - `GET /api/loupe/examinations`, `POST /api/loupe/examinations` (start), `GET /api/loupe/examinations/[id]`, `GET …/[id]/events?after=` (NDJSON), `GET …/[id]/asset?key=`, `POST …/[id]/stop`, `POST …/[id]/reevaluate`, `POST …/[id]/checks` (run a Check again, as the Owner's client).
  - `GET|POST /api/loupe/rulebooks`, `GET|POST /api/loupe/uploads`, `POST /api/loupe/tokens`, `GET /api/loupe/audit`, `GET /api/loupe/corpus` (seed data, cached).
  - `/api/loupe/mcp` checks its own bearer (no cookies, no `withOwner`) and calls the same services. There are no server actions.
- The page (`src/app/demos/loupe/page.tsx`) reads its first view through `examinations.firstView` behind `<Suspense>`.

## Rules that stay

- The Examiner reaches everything through the Loupe MCP server (`/api/loupe/mcp`, `server/mcp.ts`), in process, with a token bound to its Examination. A new capability is a new MCP tool calling a service the REST routes also call. An Examination's state is one JSON column changed only by the tools under a row lock (`ExaminationRepository.mutate`).
- The Toolkit is Python (`src/features/loupe/toolkit/loupe`, pinned `requirements.txt`) and runs in a Vercel Sandbox with no network; its packages are in a snapshot keyed by the requirements' hash (`loupe.toolkit_snapshots`, built on first use). A new Metric needs the contract (`METRICS`, `CHECKS`), the Toolkit (`contract.py`) and a Rule together. After changing the Toolkit or the Corpus run `pnpm render:loupe-corpus` (needs `uv`), which also rewrites `server/toolkit.generated.json` and `domain/corpus.generated.json`; commit them. Corpus PDFs and the Samples' `document.pdf` need `git add -f`.
- Corpus: `fixtures/loupe/` (README there; Meridia, SPECIMEN), 53 Documents in train/validation/test with a Manifest of every Tamper. `domain/golden.test.ts` scores the model-free Sweep against it. Tune thresholds on train and validation only. Samples are static files under `public/loupe/samples/`; a Sample card never says whether it was tampered with.
- Workflow: `server/workflow.ts` (`loupeExamination`) holds only pure code; every step is in `server/steps.ts`, and each step's body calls `examinerFor(id)`. Do not import a module that uses Node built-ins or `postgres` into `workflow.ts`, and do not rename or move the steps while an Examination runs.
- Data lives in the `loupe` schema (`supabase/migrations/20261119140000_loupe.sql`), on the shared pool (`db()` from `src/server/postgres.ts`), and the private `loupe` bucket (Uploads under `u/<hashed owner>/`, page images, looks and Evidence layers under `x/<hashed owner>/<examination>/`, served to their Owner by `GET /api/loupe/examinations/[id]/asset`; the Storage purge removes both folders). `loupe.owners` is the only table in `access.owned_tables`; everything cascades from it. The Trail (`examination_events`) and the Audit trail (`audit_events`) refuse UPDATE and DELETE.
- Env: `DATABASE_URL`, `LOUPE_AI_GATEWAY_API_KEY` (falls back to `DOCUMENT_COMPLIANCE_AI_GATEWAY_API_KEY`), `LOUPE_MODEL`; shares `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `RATE_LIMIT_SALT` (it signs every Loupe MCP token) and `E2E_BYPASS_TOKEN`. The Sandbox authenticates like Sieve's (OIDC on Vercel, `VERCEL_OIDC_TOKEN` locally); without it only Samples can be examined, from their recorded Sweep.
- Caps are `LIMITS` and `RUN_LIMITS` in `domain/limits.ts`, taken in the services for the app and the MCP server alike. The caps outside an Examination (a client's Checks per visitor, Re-evaluates and tokens per Owner) count `loupe.rate_events` through `loupeRateLimiter` in `repository.ts`, which implements the platform's `RateLimiter` contract: `pgRateLimiter` has no per-Owner scope and reads `<schema>.rate_hits`.
- `e2e/loupe.spec.ts` runs stubbed by default (scripted Examiner, recorded Sandbox, no spend), the MCP journey included. `E2E_LIVE=1` makes the whole spec live (the real Examiner on the page's Examinations, a real Sandbox for the MCP journey's Sweep and Check); `E2E_LOUPE_LIVE=1` adds just one real Examination (about five cents, `x-e2e-live: 1`). Run either only when asked, like the rest of the suite.
