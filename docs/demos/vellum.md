# Vellum (a vision model redraws a screenshot; code measures it): agent notes

Read this before you change `src/features/vellum/`, `/demos/vellum`, `/api/vellum/*`, `fixtures/vellum/` or `e2e/vellum.spec.ts`. The rules for every demo are in the root `AGENTS.md`; the layers are in `docs/engineering/architecture.md`.

- A live demo at `/demos/vellum` in two places (Trace, Under the hood): GPT-6.2 Astra redraws a screenshot as a vector Drawing, mark by mark, and the Ruler scores it against the pixels and sends the worst Cells back for another Pass. Domain language: `src/features/vellum/GLOSSARY.md`. Decision: `docs/adr/0034-vellum-the-model-draws-the-browser-measures.md`.
- A Drawing is data in the grammar `vellum.drawing/1` (`domain/drawing.ts`), never markup. Everything the model returns goes through `sanitizeDrawing`/`sanitizeMark` before it is drawn; the SVG writer (`domain/svg.ts`) escapes every string. A new kind of Mark changes the grammar, the sanitizer, `svg.ts` and `components/stage.tsx` together.
- Only `domain/ruler.ts` scores (pure; run in the browser by `components/raster.ts`). A later Pass gets Notes as numbers and hex only; every sentence the model reads is written by `domain/brief.ts`.
- Layers: `server/service.ts` (`VellumService`: `allowance`, `pass`) over the ports in `server/ports.ts` (`Draftsman`, `rate`), wired in `server/container.ts`. `server/api.ts` is the route stack (`sameOrigin`, `withAccess`, `withVisitor`, `withServices(vellum)`); Vellum saves nothing, so there is no Owner. The page reads its first allowance through the same service (`currentRequest()`).
- Endpoints:
  - `GET /api/vellum/allowance`: Passes used this hour, the hourly cap, the model.
  - `POST /api/vellum/passes`: one Pass, streamed as NDJSON (body up to 8 MB: three base64 images and the last Drawing). The service checks every image (`preparePass`, a 400 `InvalidError` spends nothing) before it takes the cap, then the Draftsman draws; after the first line a failure is an `error` line.
- Caps are `LIMITS` in `domain/limits.ts` (12 Passes per visitor per hour, 300 across everyone per day), taken with `pgRateLimiter` over `vellum.rate_hits`. Nothing else is saved: no Owner data, no bucket (`supabase/migrations/20261119170000_vellum.sql`; the everyone-count uses `rate_hits_kind_created_idx` from `20261128000000_rate_hits_kind_created_indexes.sql`).
- Env: `VELLUM_AI_GATEWAY_API_KEY` (falls back to `DOCUMENT_COMPLIANCE_AI_GATEWAY_API_KEY`), optional `VELLUM_MODEL` (default `openai/gpt-6.2-astra`), `VELLUM_REASONING` (`low`, `medium` or `high`; default `low`); the shared `DATABASE_URL` pool (`db()`), `RATE_LIMIT_SALT` and `E2E_BYPASS_TOKEN`.
- Samples: four fictional Meridia screens, HTML in `fixtures/vellum/` (README there), rendered to `public/vellum/samples/` with `pnpm render:vellum-samples`.
- Stubbing: an e2e request (the e2e token) without `x-e2e-live: 1` gets the container's `cannedDraftsman` (`server/pass.ts`): the canned Drawing in `domain/stub.ts` through the real reporter, sanitizer and Ruler, no model, no database write (the e2e visitor skips the cap).
- Tests: `server/service.test.ts` (a lying image is refused before the cap; the cap is taken before the model and a refusal never reaches it), `server/pass.test.ts` (image signatures, the stream reporter), and the domain tests of the grammar, sanitizer, SVG escaping, Ruler and Rules. `e2e/vellum.spec.ts` runs stubbed by default; `E2E_VELLUM_LIVE=1` asks the real model (about a dollar a Trace); run it only when asked.
